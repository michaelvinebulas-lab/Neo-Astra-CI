## 1. Why this release

The browser playground is the first release that **demonstrates the frontend and tooling half of the original Neo Astra thesis** rather than extending the language surface. It proves, in public and without a server:

- one parser and one semantic contract — the Rust core runs in Wasm, nothing re-parses `.ns` in TypeScript;
- capability modes and semantic policies are explainable — `check_project` metadata carries the mode tree, and `canonical`/`migrate` make edition choices visible;
- generated JavaScript is readable ESM, produced by the same TypeScript codegen used by the CLI;
- Nova-style direct execution is honest — a core-only sandboxed runner, with web capabilities deferred until a `web` profile exists;
- NoPM is one graph and one lockfile across every ecosystem, even when the browser can only fetch from some registries.

Recent syntax and diagnostics work becomes visible here instead of being another round of language churn.

This release does **not** close the semantic-contract pillars. `PV-01` through `PV-08` remain open in [`Pillars/README.md`](Pillars/README.md); `1.2` advances part of `PV-09` and `PV-07` only.

## 2. Locked decisions

| Decision | Choice |
|---|---|
| Editor scope | Full virtual project: file tree, real `core.json`/`core.toml` and `build.json`/`build.toml`, multi-module imports |
| Manifest formats | JSON and TOML |
| Package surface | Local modules, virtual path packages, and the full NoPM adapter vocabulary |
| Live package fetch | npm and Cargo only, behind explicit action, with Web Crypto integrity checks; others declared and injected |
| Edition controls | First-class: `0.1`/`0.2` toggle, canonical lint, `migrate` preview/apply |
| Canonical lint exposure | New `canonical` JSON-RPC command; `check` response shape unchanged |
| Sandbox runner | Core-only now; no DOM, network, or filesystem; web APIs in a later release |
| Hosting | Separate `Neo-Astra-Playground` repo, GitHub Actions → Pages |
| Versioning | Tag `v1.2.0` in the playground repo, aligned with compiler `1.2.0` |
| Distribution rule | No server, no private tree pushed to `origin`, no binary blob committed to a public repo |

## 3. Architecture

```text
Browser main thread
  ├─ virtual project store (files + manifests + lockfile)
  ├─ file tree / editors / controls / diagnostics gutter
  └─ postMessage ───────────────┐
                                ▼
Worker (single compiler host)
  ├─ CompilerBridge → astra_wasm.wasm (JSON-RPC over raw ABI)
  │    check_project, check, format, ast, explain, canonical, migrate
  ├─ browser-safe NoPM resolver + virtual store
  │    path / git / npm / cargo / pypi / nuget / oci adapters
  ├─ codegen-js / codegen-ts → per-module ESM with relative specifiers
  └─ sandboxed iframe runner with runtime shim and hard timeout
```

### 3.1 Boundaries

- `astra_wasm.wasm` is built from `crates/astra-wasm` for `wasm32-unknown-unknown`. It owns parsing, resolution, type checking, mode inference, canonical lint, migration, and typed IR.
- The browser never implements a second `.ns` parser. All syntax knowledge lives in the Rust core.
- TypeScript codegen consumes `ModuleIr` exactly as the CLI does. For multi-module projects it computes `moduleSpecifiers` from virtual paths, mirroring `orchestrator/packages/cli/src/index.ts`.
- Package resolution is browser-safe TypeScript. The Rust `astra-nopm` binary is not compiled into the Wasm module for 1.2.
- The main thread only renders. Compiler calls, codegen, package fetch, and program execution live in the Worker so a hang can be terminated.

### 3.2 Virtual project model

The project is an in-memory `Map<string, string>` keyed by project-relative path. It contains:

- `.ns` source files;
- exactly one core manifest (`core.json` or `core.toml`);
- an optional build manifest (`build.json` or `build.toml`);
- `core.lock.json` generated by the browser NoPM resolver.

Module keys passed to `check_project` are project-relative paths, matching CLI behavior. Package roots from the virtual store are added to the same graph through an `importMap`, as the CLI does for linked path packages.

### 3.3 Manifest handling

Reuse the browser-safe parts of `orchestrator/packages/manifest`:

- `CORE_KEYS`, `BUILD_KEYS`, `isCoreManifestName`, `isBuildManifestName`;
- `parseManifestSource` (JSON via `JSON.parse`, TOML via `smol-toml`);
- `validateManifestKeys` (rejects keys in the wrong manifest);
- duplicate-key detection for JSON.

Node-only helpers (`findCoreManifest`, `readManifest`, Taplo formatting) stay out of the browser bundle. TOML formatting in the playground is emitted by a deterministic serializer, not by `@taplo/lib`.

### 3.4 New compiler API command

Add `canonical` to `astra-compiler-api` and `crates/astra-wasm`:

```json
{
  "jsonrpc": "2.0",
  "id": 7,
  "method": "canonical",
  "params": {
    "apiVersion": "1.0",
    "source": { "path": "src/main.ns", "text": "..." },
    "edition": "0.2",
    "target": "js"
  }
}
```

Response:

```json
{
  "apiVersion": "1.0",
  "ok": true,
  "diagnostics": []
}
```

It wraps the existing `astra_core::canonical::check_canonical`. `check` remains unchanged. `migrate` is reused as-is for preview/apply, including `changeEdition`.

### 3.5 NoPM in the browser

A new browser-safe core module is extracted from `orchestrator/packages/nopm` with no Node imports:

- `parsePackageId`, `formatPackageId`, `parseDependencyRequest`, `createDescriptor`;
- `resolveDependencyGraph`, `resolveDependencyGraphForTarget`, `resolveForTargets`;
- `createLockfile`, `formatLockfile`, `isLockfileCurrent`;
- SHA-256 integrity via `crypto.subtle.digest` instead of `node:crypto`.

Adapter behavior:

| Source | 1.2 behavior |
|---|---|
| `path` | Fully resolved from the virtual tree |
| `git` | Declared and resolved; contents injected by URL/paste; no browser Git protocol |
| `npm` | Explicit live fetch from `registry.npmjs.org` + tarball; integrity verified |
| `cargo` | Explicit live fetch from crates.io + tarball; integrity verified |
| `pypi`, `nuget`, `oci` | Declared and locked; contents injected; clear “not fetched in browser” hint |
| `sys` | Declared only; never executed |

If a live fetch fails because of CORS or network policy, the UI keeps the resolved lock entry and offers upload/paste with the same integrity check. It never silently degrades.

### 3.6 Runtime sandbox

Generated modules are loaded in a sandboxed iframe with:

- no DOM, `fetch`, `WebSocket`, `indexedDB`, or storage;
- a `runtime` shim providing `stdout`/`stderr` capture and a deterministic clock if needed;
- a hard wall-clock timeout enforced by terminating the iframe/Worker;
- manual memory rejected by the checker for `js`/`ts` targets as usual.

`spawn`/channels are visible in check output but not executed in the 1.2 runner.

## 4. Repository and distribution

1. Create `luminousvalentine-cell/Neo-Astra-Playground` **after** this plan is approved.
2. Add `scripts/public-playground.mjs` in the private tree. It writes a sanitized standalone tree containing:
   - `apps/playground/` UI, worker, and shared browser-safe packages;
   - `packages/manifest`, `packages/nopm`, `packages/compiler-client` (browser-safe subset), `packages/codegen-js`, `packages/codegen-ts`;
   - `crates/astra-wasm` source and a CI script that builds the Wasm artifact;
   - no private docs, tests, conformance corpus, `.vscode/`, or `test_comparison/`;
   - no source comments, matching the existing public mirror policy.
3. The playground repo gets its own local clone with its own pre-push hook. The existing `-source` clone keeps its `source`/`master`-only rule. Nothing from the private tree is pushed to `origin` directly.
4. CI workflow `playground.yml`:
   - install Rust `wasm32-unknown-unknown`;
   - `cargo build --release -p astra-wasm --target wasm32-unknown-unknown`;
   - optional `wasm-opt -Oz`; warn (do not fail) above a 6 MB budget;
   - build the TypeScript app;
   - deploy `dist/` to Pages on pushes to `main` and on `v*` tags;
   - run browser smoke tests on every PR.
5. Tag `v1.2.0` in the playground repo only after the compiler `1.2.0` release is green.

## 6. Definition of done

- Public playground repo exists, Pages is live, and the static app needs no server.
- A user can create a multi-file project, edit both manifest formats, check/format/view AST/explain, switch editions, preview migration, generate JS/TS, and run core-only programs.
- Generated output and diagnostics match the native CLI for the fixture set — this is the vision proof.
- NoPM produces the same `core.lock.json` shape as native `nopm`; live fetch is explicit, integrity-checked, and falls back honestly.
- The compiler `1.2.0` and playground `v1.2.0` tags are in sync.
- The plan explicitly states that `1.2` is a frontend/tooling proof, not a semantic-contract proof; the remaining pillars stay in [`Pillars/`](Pillars/README.md).

## 7. Risks

| Risk | Mitigation |
|---|---|
| Wasm size / compile time exceeds budget | Release build + `wasm-opt`; warn at 6 MB; profile before adding features |
| npm/Cargo CORS or tarball layout differences | Explicit fetch only; upload/paste fallback with the same integrity check |
| Browser TOML formatting differs from Taplo | Deterministic serializer, documented as playground-only; CLI remains authoritative |
| Runaway generated code | Terminate iframe and Worker; wall-clock timeout; no shared mutable state |
| Accidental private-source leak | Dedicated export script, dedicated clone, review diff before first push |
| Scope creep into `web` mode | Runner stays core-only; web capabilities are a later release |

---

## 8. Out of scope for 1.2

- `high` mode and its implicit entry point (`1.3.0`).
- Wasm execution backend, direct machine code, and new language targets.
- Browser Git/OCI protocol implementations.
- A hosted registry or user accounts.
- Running `spawn`/channels in the playground sandbox.
- Any change to `spec-v0.1.md` or `spec-v0.2.md`.
- The semantic-contract pillars `PV-01` through `PV-08` except for the tooling subset described above. They are tracked in [`Pillars/`](Pillars/README.md) and worked one at a time.
